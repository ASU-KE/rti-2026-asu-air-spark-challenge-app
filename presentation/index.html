Arizona State University · Research Technology The Idea

Consensus under unequal information

Our demo: a criminal jury reaching a verdict

6 jurors hold an opinion (Guilty ↔ Not-Guilty) and update it each round. Prosecution and Defense push evidence at them. Jurors talk only to ring neighbors — so information spreads unevenly.

  • Every agent = opinion (0–1) × confidence × a Value (A / B)
  • Attorneys reach all jurors; jurors reach only 2 neighbors
  • Run ends on consensus (low variance = verdict) or a hung jury
Source: docs/planning/scenario-experiment-design.md (Criminal Jury Trial), CONTEXT.md, docs/adr/0001
Arizona State University · Research Technology The Mechanics

One round, four beats — then repeat

How opinions actually move

BEAT 1
Pick evidence
Each team draws 1 of its 10 items
→
BEAT 2
Present to jury
Defense, then Prosecution → all jurors
→
BEAT 3
Update opinion
Only if evidence Value = juror Value
→
BEAT 4
Talk to neighbors
Ring peers exchange, then re-update
↺
Evidence influence
Δ opinion = opinion-delta (−1…+1) × strength (0…1)
Applied only when the evidence's Value matches the juror's Value (A/B) — otherwise no effect. Confidence shifts by the same delta × a fixed factor. Every number is researcher-configurable.

Verdict

Opinion variance drops below threshold → consensus reached.

Hung jury

Round limit hit with no consensus.

Arizona State University · Research Technology Where We Got Blocked

The honest part — model performance & consistency

Capable models were slow; autonomy was brittle

Good but slow

Qwen 3 (27B) gave strong output but ran very slowly. We tried a different model just for the orchestrator.

Off the rails

Given a frontend ticket, an orchestrator hallucinated the branch name and built backend code instead (Qwen 3 VL 32B Thinking).

Parallel collision

Multiple agent workflows on one repo broke the project — a shared tree can't hold concurrent threads.

Our own errors

Initial scaffolding runs failed on mistakes we made — logged, not hidden.

This is exactly the stress test we wanted: the aSDLC's "avoid collisions / keep humans accountable" controls, tried against reality.

Source: team status update, 2026-09-03. Model identifiers as reported by the team; to be confirmed for the record.
Arizona State University · Research Technology Lessons & Response

What we changed the moment it broke

Isolate agents · verify the branch · pick the right model · cut scope

Problem

Agents collided

Fix One repo clone per agent thread.

Problem

Wrong work built

Fix Human checks work matches the ticket, not just that it runs.

Problem

Too slow

Fix Speed & consistency are first-class; faster model for the orchestrator.

Problem

Over-scoped

Fix Dropped cloud + auth; design the framework, build one slice.

Every reversal became a documented decision — an ADR, a revert, a scope note — so the failure turned into pilot evidence, not a hidden exception.
