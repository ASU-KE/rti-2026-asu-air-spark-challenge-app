Arizona State University · Research Technology Office What worked—and what failed

Candid hackathon evidence

The architecture held; time and orchestration did not

Worked

Specification before implementation

Glossary and ADRs prevented Role, Persona, Network, and Context Shell concepts from drifting.

Small, test-first foundations

Atomic red → green commits created inspectable API, validation, and secret-handling behavior.

Defensive model boundary

Labeled Markdown, one repair retry, and carry-forward keep malformed output from ending a Run.

Blocked or failed

Full Run not completed

Available capable Models were too slow for the remaining hackathon window.

Wrong work, confidently delivered

A frontend ticket reportedly produced backend work after orchestration drifted from the requested branch and scope.

Shared-tree collision

Parallel workflows in one working tree interfered with each other.

Arizona State University · Research Technology Office Lessons and next experiment

Turn each failure into a control

Isolate · verify · measure · narrow

Collision: parallel workers changed one tree.
→
One isolated clone or worktree per Agent thread.
Scope drift: work ran but did not match the ticket.
→
Validator checks ticket, branch, and changed files—not only tests.
Latency: capable Models consumed the demo window.
→
Benchmark vision + reasoning + response time before orchestration.
Scope: framework ambition exceeded 48 hours.
→
Design the framework; build one tracer-bullet Run first.
